// Notas arquitectónicas
  • Desacoplamiento por interfaces: cada componente expone interfaces explícitas (IRestAPI, IAppService, IRepository, etc.) y los dependientes se acoplan solo al contrato, no a la implementación.
  • Motor de recomendación extensible: RecommendationEngine ejecuta IRecStrategy; añadir una estrategia solo requiere implementar la interfaz y registrarla en RecommendationConfig.
  • TMDB como adaptador aislado: TmdbClient es el único punto de contacto. Ningún otro componente conoce la API REST de TMDB.
  • Persistencia encapsulada: IRepository oculta JPA/Hibernate. Los servicios superiores nunca dependen de entidades JPA directamente.
  • Transversales desacoplados: Security, Configuration y Observability envuelven el flujo principal sin acoplarse a la lógica de dominio.
  • Configuración centralizada: todos los componentes consumen IConfiguration para leer propiedades, pesos de recomendación y perfiles.
